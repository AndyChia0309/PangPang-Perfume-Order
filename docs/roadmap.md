# 規劃與需求

之後想做的功能，還有做過的功能當初怎麼規劃的。新想法先丟進「未來實作」，真的要開始做再另開一節，記下怎麼拆步驟、做了哪些決定。

## 未來實作（2026-09-30 決定先暫緩）

- [ ] **訂單管理頁**：登入後看所有訂單、依狀態篩選、改成已付款／已出貨
- [ ] **匯款回報與出貨通知**：顧客在網站輸入訂單編號和帳號末五碼；出貨時寄信通知
- [ ] **H2 訂單查詢**：用訂單編號 + Email 查訂單內容和狀態（見下方「歷史訂單」）

## 功能規劃：自動寄信

2026-09-29 決定不做會員登入，訂單資訊直接寄 Email 確認信給顧客。我沒有自己的網域，所以先用 **EmailJS + 店家 Gmail** 寄信（免費方案每月大約 200 封）。之後如果買了網域，可以換成 Cloudflare Email Service。

- [x] **E1 EmailJS 設定**：連結 Gmail、建「顧客確認信」和「新訂單通知」兩個範本、打開非瀏覽器 API 存取
- [x] **E2 Worker 寄信**：訂單寫入成功後寄兩封信，寄信失敗不影響下單（`ctx.waitUntil`）。程式在 `worker/email.js`，兩封信中間隔 1 秒，因為 EmailJS 每秒只能打 1 次（`df32925`）
- [x] **E3 部署與測試**：設定正式環境的 secret，成功視窗改成「確認信已寄到您的 Email」。正式網站下單後，顧客和店家都有收到信（`df32925`）

## 功能規劃：歷史訂單

現在顧客關掉成功視窗之後，就看不到訂單編號，也沒辦法回頭查自己的訂單。原本打算分兩階段做：

- [~] **H1 我的訂單（存在瀏覽器）**：2026-09-29 決定不做。這個網站就是一個單純的訂購表單，不做會員，顧客看 Email 確認信就好（見「自動寄信」）
- [ ] **H2 訂單查詢**：輸入訂單編號 + Email，Worker 去 Supabase 查訂單內容和最新狀態，換裝置也能查。跟訂單狀態（匯款回報、出貨）一起做比較合理。**2026-09-30 移到未來實作**
